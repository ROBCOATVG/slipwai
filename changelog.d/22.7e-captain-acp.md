**The captain's drives can run over the Agent Client Protocol.** The toolkit carries the keel's protocol
client (`scripts/agents/acp.py`, written by `make shared`), and `scripts/agents/drive.py` is a `/sail`
session on it with a process's face: the captain's watch on the deck log drives it as it drives a print
session, the agent's words and tool calls are lines in the fleet's stream, the model `cruise.json` names is
set where the agent offers it, and a stop is the protocol's cancel. Nobody is in the berth, so a write
inside it is allowed this once, one outside it refused with a line, and a question declined; a stage that
must ask parks on a `question` line as it did. The skipper's round takes the same way. Opt-in by
`SLIPWAI_ACP`: `1` takes the initialised harness's launch row, any other value is the command that starts
an agent. Unset, every drive runs in the harness's print mode exactly as it did; the launch rows are
unproven, and the board will turn this on for a project once one is.

**Catch-up:** the two scripts arrive with the toolkit on `slipwai migrate`; nothing changes for a project
that does not set the variable.
